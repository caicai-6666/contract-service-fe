# 智能助手会话交互

> 本文说明合同库对话的输入、轮次生命周期、流式展示与恢复边界。已接入 Communication API；正式后端目前只激活轮次并发送心跳，尚不调用工作流，不会自动生成答复。

## 通信接口与轮次

接口通过统一鉴权请求入口访问 `/contract/api/communication`，开发环境路径规则与[前端登录与鉴权](../platform/authentication.md)一致。

| 操作 | 方法与相对路径 | 前端行为 |
| --- | --- | --- |
| 会话列表 | `GET /conversations` | 登录后读取当前用户持久化会话，无查询参数；服务端顺序与名称为准 |
| 修改名称 | `PATCH /conversations/{conversation_id}` | 仅 JSON `name`，成功后采用返回的名称与原创建时间 |
| 删除会话 | `DELETE /conversations/{conversation_id}` | 二次确认，无请求体，204 后移除本地记录并断开订阅 |
| 打开历史 | `POST /conversations/{conversation_id}/open` | 无请求体，读取完整驻留范围，不创建或激活轮次 |
| 更早历史 | `POST /conversations/{conversation_id}/refresh` | open 后向前扩展，无客户端游标；完整替换历史范围 |
| 创建会话及首轮 | `POST /conversations` | multipart 提交原文、重复 `files` 字段，可选 `name`；201 返回服务端会话及首轮 ID |
| 追加或替代轮次 | `POST /conversations/{conversation_id}/turns` | 已注册会话提交原文、重复 `files` 字段及可选 `supersedes_turn_id`；成功为 201 |
| 订阅 | `GET /conversations/{conversation_id}/turns/{turn_id}/events` | 带 Bearer 的流式 Fetch，201 后立即订阅激活 |
| 恢复 | `GET /conversations/{conversation_id}/turns/{turn_id}` | 快照替换该轮展示，读取本身不激活轮次 |
| 停止 | `POST /conversations/{conversation_id}/turns/{turn_id}/cancel` | 无请求体，以返回快照确认终止 |

空白会话的客户端 UUID 仅用于本地草稿定位。首次发送调用会话创建接口，由后端创建持久化会话、工作区并注册首轮；成功后替换为服务端会话 ID 并记录已注册状态，后续发送、替代、订阅和恢复均使用该 ID，不再次创建会话。用户提前手动命名时提交可选 `name`，否则省略以采用后端默认名称；前端展示标题仍沿用下述命名规则。旧本地缓存中已有轮次的会话按已注册处理，后端不存在时展示错误，不静默另建会话。发送前校验文字最多 20000 字符、附件最多 10 份、单份非空 PDF 不超过 10 MiB、总量不超过 20 MiB；文字和附件至少有一项。201 后才清空输入和附件；失败保留草稿，不自动重试创建。网络中断可能导致创建结果不确定，前端明确提示，不将重复提交当成幂等操作。

首次订阅立即执行，不等待消息动画，以遵守服务端激活期限。`processing` 表示轮次已激活，不代表模型已经执行。`message.completed` 只完成一条消息；仅轮次终态停止等待。`error` 单独出现不自动结束轮次。

## 事件展示与恢复

### 处理耗时

回复完成（或手动停止且内容显示完整）后，hover 操作区在复制按钮旁显示本轮开始处理时间，来自 `activated_at`，按浏览器本地时区展示日期与时分。实时事件和快照采用 ISO 时间，历史记录的 Unix 毫秒统一转换；未激活或旧记录时间未知时不显示，不拿消息接收时间、会话创建时间或当前时间代替。

时间文案按“今天 → 本周 → 今年 → 往年”优先级缩略：今天仅时分，本周显示周几及时间，今年其他日期省略年份，往年保留完整日期。本周以本地周一零点至下周一零点为界，可跨年；hover 或键盘聚焦操作区时重新判断，完整日期保留在时间提示和无障碍标签中。

快照及 `turn.status` 均保留 `activated_at`、`finished_at` 和 `processing_duration_ms`。每条用户消息下方、助手回复之前独立展示“已经处理 x 秒”，下方为横向分隔线，不放进黑色消息气泡。处理中以 `activated_at` 为起点，每秒更新整数秒数；断线等待也计入，不从创建时间或重连时间重新计时。客户端时钟偏差会影响运行中的估算，负值钳制为 0。

激活后计时行平滑展开并淡入，不因每秒更新重复播放入场动画。没有进度或异常时，空状态容器不占列表间距，分隔线与“正在思考”保持紧凑留白；减少动态效果时直接显示最终布局。

收到终态后停止实时计时，改用服务端固定的 `processing_duration_ms`。手动取消时同一行改为“你在 x 秒后手动停止”，方向调整导致旧轮次被替代（`superseded`）时改为“你在 x 秒后调整了方向”，其他终态保留“已经处理 x 秒”；不在助手消息顶部或底部进度区重复展示耗时。未激活直接结束的服务端耗时为 0；缺少权威终态耗时时不使用本地时间冒充，被替代轮次暂时显示“已调整任务方向”。正常终态直接读取事件中的时间，不额外请求快照；替代操作提前关闭旧流且缺少旧轮次耗时时，单独通过旧轮次快照补齐并更新提示。刷新使用快照时间恢复，离开合同库时不持续刷新计时 UI。

### 回放与状态

`can_interrupt` 是停止及调整方向的唯一许可字段：只有服务端明确返回 boolean true，且任务仍为非终态时才开放。创建响应、快照、`turn.status` 均更新此字段，缺失按 false；open/refresh 使用任务条目顶层当前值，不从历史轨迹推断。比本地 SSE 游标更早的历史响应不覆盖较新的权限，终态一律关闭，浏览器恢复缓存不保存授权。

同一轮可先收到 `processing, can_interrupt=false`，随后收到新的 `processing, can_interrupt=true`；按事件序号处理，不能按状态名称去重，也不因权限开放重启计时。未许可时停止按钮和“调整方向”按钮禁用，请求层再次检查；用户仍可输入、添加或删除排队消息，正常结束后自动发送下一条不受该许可限制。取消或替代遭遇 409 时保留原 SSE 和队列，不伪造取消成功，可通过快照更新当前状态后等待后端信号。

- 按 SSE `id` 去重，使用十进制字符串保存游标并以 BigInt 比较，重连携带 `Last-Event-ID`；心跳注释不显示、不占序号。
- `message.delta` 按轮次与消息 ID 追加，`message.completed` 使用完整文本及引用。必须保留 `intermediate`/`final` 类型，不推断默认类型；同一消息类型和生命周期不一致时恢复快照。
- 仅消费 `turn.status`、`task.progress`、`message.delta`、`message.completed` 和 `error` 五类事件。校验期间保持 `processing`，校验进度使用 `task.progress`，文件保留、剔除及原因使用普通消息展示并随快照恢复，不另设校验卡片或字段；不再兼容旧 `gate.result` 事件及 `gate_result` 字段。需要用户确认时以 `final` 提问并正常结束本轮，明确拒绝则由 `rejected` 终态结束，不依据校验文案推断状态。
- 只有 `turn.status` 携带事件时间；进度、消息（包括 final）和错误不依赖 `created_at`。排序、去重和回放只使用 SSE `id`，任务计时只使用状态事件或快照的激活时间及固定耗时，不为中间事件补造时间戳。
- `task.progress` 在尾部展示当前状态。同类型连续更新复用同一项；被其他类型或消息接替、取消、替代或进入终态时，联网检索和本地检索保留图标及文字，停止高光并变灰，只有“正在思考”消失。保留项属于处理过程，随 final 或手动停止一起折叠，可再次展开，不参与回复复制。契约没有独立的步骤完成事件，变灰只表示不再是当前展示状态，不推断工具成功。保留项来自本页实际接收的事件；快照只提供最近进度，刷新后不伪造缺失的完整进度历史。
- 进度的 `type` 和 `message` 均必填，SSE 与快照采用同一校验。类型只接受 `online-search`、`local-search`、`thinking`，不解析文案推断类型，不兼容缺少类型的旧结构。联网检索展示 `online-search.webp` 与“正在联网检索”，本地检索展示 `local-search.webp` 与“正在查阅资料”，思考仅展示带间歇高亮的“正在思考”，不加图标。图片保留原始 PNG 作为素材，页面仅引用 WebP。界面使用契约默认文案减少噪声，同类型更新不重复播放切换动画，进度不再复制为后续消息标题。
- 检索状态在首次事件到达时就以固定 ID 和位置进入消息序列，后续仅更新该项的活动状态；结束不新增灰色副本，也不通过尾部退场动画重复展示。文字增量或消息完成不会重置类型阶段，同类型进度即使穿插在消息中也复用原记录；只有收到不同类型后再返回检索才新建阶段。快照缺少进度与消息的顺序信息，已有消息时不恢复可能过时的进度；要精确恢复正在运行的工具步骤，需要后端补充结构化步骤状态或事件序号。
- 引用显示合同标识摘要及可用页码，暂不推断 PDF 地址或跳转接口。
- 取消、替代等终态在原问题旁标记；已生成的中断文本保留展示，不视为可继承的模型上下文。
- 断流、409 游标冲突、序号缺口或 `replay_required` 先获取快照，再以快照游标重连。自动恢复采用退避，连续 5 次失败后显示“恢复连接”；不会创建新轮次。410 通过快照呈现过期状态；404 明确提示轮次已清理或不可访问；401 沿用全局退出登录。
- `turn_unavailable` 等连接级终止错误停止自动重连，保留状态待确认，并提供快照恢复入口；不伪造轮次已取消。

切换前端页面或会话不取消后台轮次，已挂载组件保留独立连接。组件卸载只断开网络，不发送取消。当前标签页将会话名称、选中会话、用户消息展示记录和轮次定位信息保存到 `sessionStorage`，以登录凭据的 SHA-256 摘要隔离缓存，不额外保存密码、明文令牌或文件字节；刷新后读取已知轮次快照恢复助手输出。存储不可用时退回页面内存。后端记录清理或重启后无法恢复的内容会明确提示。

登录初始化时读取服务端会话列表；首次创建会话后再次刷新，页面内部切换不重复请求。列表保留服务端的创建时间倒序及同毫秒 ID 倒序，不按改名、轮次状态或本地活跃时间重排。响应映射 `conversation_id`、`name`、`created_at`，校验字段类型、毫秒时间及重复 ID；空数组只保留本地新对话入口。503 或格式错误保留当前列表并在菜单显示重试，401 沿用登录失效处理。

按会话 ID 合并本地用户消息与可恢复轮次，名称和创建时间采用服务端值；列表首部保留未注册的新对话草稿。仅在服务端存在的会话也标为已注册，后续调用轮次接口，不因本地消息为空而再次创建会话或覆盖服务端名称。会话列表本身不包含历史，历史通过下述 open/refresh 加载；未归档且已丢失的内存轨迹仍无法恢复。当前没有分支功能，也不据此推断模型上下文继承。样式联调服务可经部署代理使用相同接口，不在前端内置模拟答复。

### 持久化轨迹与顶部加载

初始化恢复、切换会话及重新打开历史时，消息区先保持透明但参与布局；等待历史请求结束、最后一个问题置顶和布局提交后，再整体淡入。快速切换只允许最后一次定位完成后显示，旧请求不提前揭示其他会话。向前加载更早记录保持当前内容可见，继续采用阅读锚点补偿。

选择已注册会话时调用 open，初始化恢复选中会话及首次创建后也读取一次。重复打开接受后端完整驻留范围，不主动清空已加载内容。同一会话的 open/refresh 串行，失败保留旧视图；409 提供“重新打开”，不无限自动重试或把所有冲突当成缓存丢失。切换到其他会话后，旧请求只更新其所属会话；删除后的迟到响应丢弃。

响应中的 records 是完整任务集合，按原始 sequence 正序替换历史投影，不整段追加；允许摘要导致的序号间隔。是否有更早历史只使用 has_more，records 为空且 has_more=true 时仍提供入口。滚到顶部后继续向上滚轮，或手指下拉达到阈值并松开，加载一次更早历史；同一连续滚轮手势不连发，正在加载和 has_more=false 时不请求。顶部还提供可键盘操作的点击入口。加载前暂停末尾跟随，DOM 更新时按原可见消息锚点补偿 scrollTop，避免新增前文或尾部记录改变当前阅读位置；无可见锚点时保留原滚动位置。

每个任务的 `payload.input` 显示用户原文与文件卡片；`payload.events` 按原 SSE 序号恢复 `turn.status/task.progress/message.completed/error`，允许过滤 delta 后的序号间隔。消息按 `message_id` 覆盖完整正文、状态和引用，不重复拼接；随后用 `streaming_messages` 覆盖仍在生成的正文。检索进度复用实时展示规则，同类阶段不重复增加图标，结束后变灰，只有思考提示消失。最终答复沿用过程折叠和最后消息复制规则，已有正文完整显示，不重播打字动画。非法结构、倒序事件和跨轮次数据提示错误，不静默跳过。

`event_source=legacy` 仅恢复后端聚合的旧消息及原有引用，不补造进度、错误或游标，生命周期采用外层任务状态。过渡期仍兼容旧版后端直接返回的 `payload.trace`，仅该旧格式保留原工具摘要展示；所有后端完成展示事件升级后可移除此回退路径。

历史 processing_duration_ms 为固定耗时，复用已完成、手动停止和方向调整的提示。null 不作为 0，也不以 created_at 估算耗时；无耗时的手动停止仅显示状态。model_context_start_sequence 只保留为后端窗口标记，不用于隐藏历史或人为计算分页。

历史投影与本地 SSE 状态分开维护。本页实际创建或恢复接续的轮次优先，不因停止后变为终态就被旧归档覆盖；其余同 turn_id 的已归档终态使用历史版本，尚未归档的本地消息继续保留。`recorded` 的 pending_activation/processing 任务使用 `payload.last_sequence` 接续 SSE，此游标包含未保存的 delta，不能用最后一个展示事件序号代替；已有本地轮次不重复订阅。终态和 legacy 历史只恢复展示，不订阅或重新执行。历史内容不复制到 sessionStorage，刷新后重新 open。

`recorded` 消息引用沿用 SSE 的 `document_id/page_number`，保留真实页码；legacy 引用沿用 `type/location`，web 仅接受 HTTP/HTTPS 并安全打开，contract 暂展示文件引用地址。空历史是有效结果，不生成演示消息。

open/refresh 的 `input.files` 保留 `file_id/file_name/file_path/admission`。新附件的 `pending`、`unavailable` 状态允许路径为 null，只展示文件名卡片，不提供打开入口；`accepted` 保留与 UUID 对应的 `/{file_id}.pdf`，不要求已落盘。旧附件没有 admission 时保留已有路径，但不默认开放预览。刷新会同步本页轮次的附件元数据，不覆盖本地 SSE 正文或重复添加消息。

已加载附件仅在明确 accepted、路径匹配且任务为 processing/completed/cancelled/superseded/failed 时可点击。读取使用带 Bearer 的 `GET /resource/conversations/{conversation_id}/files/{file_id}`，不发送路径、查询参数或请求体；原始上传 PDF 以 Blob 交给现有预览弹窗，不缓存响应，不显示正式合同工具栏。加载中使用原有动画，失败在弹窗中提示，可关闭后重新打开；关闭、切换会话或离开页面时取消请求并释放临时 URL，忽略迟到结果。404 不自动 open/refresh；更早附件需由用户先加载对应任务。前端入口限制不替代后端归属、准入及驻留校验。

## 空会话与首次发送

输入校验通过后立即清空输入框、展示用户消息及“正在思考”，不等待创建接口返回。注册中的消息仅为临时展示，不伪造 turn_id、激活时间或恢复缓存；201 后保持消息标识并绑定真实轮次，立即订阅。创建失败移除临时消息，在仍处于原会话且输入框未被修改时恢复文字和附件，保留错误提示；队列发送失败仍由队列保留原输入。

空会话展示手绘提示，提示层独立于输入框高度，不随输入框伸缩移动。

用户首次发送消息时：

1. 手绘提示淡出，不再向上移动。
2. 首条用户消息在 header 下方置顶位置原位淡入，不再从输入框大幅上浮或额外延迟。
3. 服务端事件独立接收，回复状态沿用入场过渡，不用定时器生成助手消息。
4. 后续用户消息使用较短的上浮进入动画，助手内容根据真实事件更新。

点击发送后，从注册请求进行中到拿到轮次 ID、等待首次激活事件，统一显示间歇高亮的“正在思考”，不显示“正在发送”“正在连接”或提前开始计时。只有收到 processing 状态及有效 `activated_at` 后，才在该条用户消息下方显示“已经处理 x 秒”；首次订阅 HTTP 建连本身不作为计时依据。轮次处理中且暂无流式消息时继续显示“正在思考”，不再使用三个跳动圆点。该文案仅为等待反馈，不表示后端已执行模型推理；断线恢复时显示连接状态，终态后移除。系统减少动态效果时保持静态文字。

等待回复且草稿为空时，发送按钮切换为白色方形停止图标；点击后调用取消接口，成功快照确认后才结束等待。取消失败允许重试，409 竞争先读取快照，不覆盖已经完成的轮次。其他会话不受影响。

从首轮注册请求发出、等待激活到处理中，均可输入新问题、添加或移除下一条消息的附件；再次发送先加入当前会话的前端队列，不并发注册轮次，不受 `can_interrupt=false` 限制。注册中及未收到可中断信号时，停止与调整方向按钮禁用，队列仍可删除。收到允许信号只启用操作，不自动执行方向调整。队列以紧凑卡片排列在输入框上方，与当前草稿附件分层展示，不撑高输入框。当前轮次正常 `completed` 后按先进先出顺序逐条调用创建接口，不携带替代 ID；手动停止、失败或其他非正常终态不自动继续队列。自动提交失败时暂停，保留该条文字和 PDF 文件并标记等待重试，不自动重复创建。

每条待发送消息右侧提供“调整方向”，点击后立即调用同一创建接口，在当前轮次仍活跃时携带 `supersedes_turn_id`，无活跃轮次时为普通发送；只有注册成功才从队列移除。每条消息另有独立删除按钮，未发送时可移除且不请求后端，已开始提交的条目禁止删除。旧轮次仅在创建成功后标为已被替代，失败不擅自取消旧轮次。新轮次不自动继承旧文字和文件。

队列目前只保存在本页内存，按会话隔离；切换模块或会话可保留，刷新、关闭页面或退出登录会丢失尚未发送的队列及其文件。服务端没有独立队列接口，排队不等于后端已收到输入。

系统启用减少动态效果时，不执行上述位移和渐变动画，但保持相同的最终布局与状态变化。

## 输入附件

输入框支持粘贴剪贴板中的文件及截图：PDF 直接加入，支持的图片沿用转换 PDF、数量/大小校验、去重和预览流程，不会因粘贴自动上传。普通文字以及文件与文字混合粘贴保留原生文字输入行为；不解析剪贴板 HTML、不读取文字中的本地路径。转换期间再次粘贴文件会提示稍后重试，不并发转换；上一条消息注册中仍可为下一条消息粘贴附件。操作系统或浏览器未向粘贴事件提供文件字节时，仍需使用“＋”选择文件。

点击输入框的“＋”可多选本地文件，已选附件以紧凑的名称标签悬浮排列在输入框上边缘外侧，不参与输入框高度计算。新增标签从右侧滑入并淡入，添加或移除附件不会撑高输入框；消息区底部保留附件栏所需的阅读留白。长名称使用省略号，悬停可查看完整文件名；每个标签右侧均可单独移除，移除后允许重新选择同一文件。

移除附件时，标签淡出并平滑收窄，后续附件随之连续补位；最后一个附件退出后隐藏附件栏。系统启用减少动态效果时直接完成移除。

选择附件后，PDF 直接保留；PNG、JPG、WEBP、GIF、BMP、AVIF 图片在浏览器内逐份转为同名单页 PDF，复用合同处理流的转换逻辑，透明区域填白，最长边限制为 4096 像素。动图仅取解码时的单帧，不保留动画。转换期间显示状态并暂停添加和发送，转换成功后即可点击名称，复用现有 PDF 预览弹窗、加载动画和整体淡入效果。

不支持的格式（包括 Word、Excel）或图片转换失败时，不加入附件列表；对话内容区顶部、header 下方按原文件名水平居中提示，不使用页面全局浮层、不占据消息布局，6 秒后消失，也可手动关闭，不影响其他成功文件。失败文件可重新选择。转换和预览均不发送网络上传请求，也不显示正式合同操作工具栏。清除按钮独立于预览入口；关闭预览、切换页面或组件卸载时释放预览临时地址，图片转换临时地址在成功或失败后均释放。

再次选择会追加附件，相同名称、大小及最后修改时间的文件不重复添加。附件始终保持单行，超出宽度时可横向滑动查看；隐藏滚动条，左右边缘采用渐变羽化，并预留边缘内距以完整展示首尾附件，不挤占额外的对话高度。点击发送后，PDF 字节通过 multipart 上传；创建轮次成功才清空附件。后端目前只暂存输入，不执行附件分析或 PDF 安全验证。

发送成功后，附件卡片位于文字气泡上方，两者作为同一条用户消息整体右对齐。卡片包含文件图标、实际上传的 PDF 名称和格式，长名称省略并通过悬停显示完整名称，多文件随可用宽度换行；仅发送文件时不显示空文字气泡或补写用户未提交的问题。附件名称随用户展示记录在本标签页恢复；不保存文件字节、不提供已发送文件删除入口。预览须先由 open/refresh 获得实际文件 ID 和准入状态，遵循上面的资源读取规则。

## 会话名称

本地未注册的“新对话”入口不显示改名和删除按钮；首次发送成功、服务端会话创建后才显示这两项操作。不按名称判断是否为新会话。

首次发送后，当前“新对话”使用首条问题生成名称，并同步显示在当前会话标题和历史会话菜单中。

命名完成后，历史菜单顶部立即补充一个新的空白“新对话”；当前会话保持激活，用户可随时切换到该空白会话继续提问。每个会话独立维护回复状态，切换到新会话时不会被其他会话中尚未结束的回复锁定。

- 连续空白归一化为一个空格。
- Markdown 消息取首个有效文本行作为名称，并去除常见的标题、列表和行内格式标记。
- 名称保留前 `12` 个字符。
- 超出长度时追加 `…`。
- 仅发送附件时优先使用首个附件名称；无法取得名称时使用“附件分析”。

历史菜单中的每个会话均可原地重命名。`Enter` 或点击输入框外保存，`Esc` 取消；名称原始长度为 1～200 个字符且不得全为空白，不压缩名称内部空格。已注册会话通过 PATCH 保存，成功后才更新名称与创建时间、不改变排序；失败保留原名称和编辑内容并显示错误，可重试。请求中禁止重复保存与同会话删除。未注册草稿仅在本地改名，首次创建时通过 `name` 提交。

所有权限等级均可在历史菜单删除本人会话。删除使用自定义顶层模态弹窗及磨砂遮罩，不使用浏览器警告框。用户必须逐字输入“我确认删除”加当前完整会话名称（不加引号），按钮才可用；弹窗和提交处理再次校验，不忽略空格或使用模糊匹配。弹窗仅提示关联记录永久删除、待发送队列清除且不能撤销，不额外展示任务及文件清理边界提示。实际删除仍不会取消后台任务，也不删除上传文件或正式合同。提交前支持取消、Escape 和点击遮罩关闭；请求中禁止关闭或重复提交，失败保留输入并在弹窗内显示错误以便重试。模态打开后聚焦输入框并限制焦点在弹窗内。204 后移除本地会话、清空该会话队列、断开本地 SSE，不改写轮次为 cancelled；删除当前会话后选中保留的新对话入口。404、422、503 等失败保留本地记录，401 沿用全局认证处理。修改或删除期间失效的旧列表响应不覆盖新结果。

该规则仅用于前端展示命名，不代表后端会话标题契约。

## 消息呈现

消息区采用简约正文流：用户消息靠右，以黑底白字的圆角矩形包裹，内部 Markdown 标题、链接、代码和表格同步适配深色背景；助手消息不展示头像、徽标、气泡边框或阴影，直接以正文形式展示。

header 独立占据布局高度，消息滚动视口从 header 下方开始。发送新问题（含队列实际发出）时将该用户消息置于视口顶部并保留 24px 阅读间距，以下预留当前屏幕的回复空间；模型输出未填满该空间时保持位置，超出后才继续向下跟随。空间通过消息容器最小高度提供，随回复填充而消耗，不在回复末尾不断追加整屏空白。主动上滑立即退出跟随，后续内容到达不拉回；再次到底部恢复。切换或刷新恢复会话后，默认置顶最后一条用户消息；即使已有长回复，也不立即追到答案末尾。切换会话时清除旧的置顶预留，再根据新会话最后一个问题计算。

滚动到末尾后自动跟随实际渲染内容的高度变化，包括流式文字和过程区折叠。主动通过滚轮、触摸或键盘上滑时立即停止跟随，历史定位同样暂停；再次滚到底部恢复。跟随采用逐帧定位而非反复启动平滑滚动，不干扰流式文字动画；离开模块时清理观察器和滚动监听。

置顶预留同时响应内容结构变化：顶部历史加载提示移除时，即使容器因最小高度约束没有发生尺寸变化，也重新计算位置，避免首条消息滑入 header；这不会重新开启用户已取消的跟随。

上下布局中，对话视口高度由浏览器可用高度确定（最少 600px），不随消息预留高度增长；长内容在消息区内部滚动。

用户与助手消息均支持 Markdown，覆盖段落、标题、列表、引用、链接、行内代码、代码块和表格等常用语法。为避免将消息内容直接注入页面，原始 HTML 不参与解析；消息中的链接在新窗口打开，并使用安全的窗口隔离属性。

助手流式增量在展示层以约 180 毫秒的短缓冲逐帧追赶，按 Unicode 字素补齐，避免网络分块直接整段跳出；通信层仍即时保存原文与游标。Markdown 按顶层正文块更新，未改变的块不重复替换 DOM。首次挂载直接显示已有内容，不重播历史；正常完成后收完短缓冲，取消/中断、非前缀快照替换、离开页面或减少动态效果时立即显示权威文本，卸载时清理动画帧。复制始终使用服务端原文，不复制尚未追赶完的视觉文本。

对话中的流式 Markdown 额外保留约一行底部缓冲，并记录该消息在当前栏宽下已经占用的最大高度。语法识别让正文变矮时用留白补齐，后续输出复用这部分空间，避免末尾跟随因高度回缩而带动分隔线向下反弹。完成时不突然收回缓冲；调整栏宽重新测量，重新挂载的静态历史不添加流式占位。过程区主动展开、折叠仍遵循原有布局动画。

助手消息顶部仅用于操作说明：新消息接替尾部步骤时，保留该步骤最新的 `task.progress.message` 作为操作说明。不显示“阶段消息”“正在回复”“回复完成”等通用占位标签，没有操作说明时隐藏该区域。当前快照未提供步骤与消息的对应关系，刷新恢复时不推断缺失的操作说明。消息底部提供复制；桌面端仅在悬停消息或键盘聚焦操作区时显示，触屏设备保持可见。“复制”保留回复的原始 Markdown 文本。

收到第一条 `final` 的 `message.delta` 即自动平滑收起该轮全部 `intermediate` 过程消息，同时开始展示流式结果，不等待 final 完成；直接收到完整 final 也执行同样的折叠。用户原问题、计时行和最终结果保留展开，尾部过程状态隐藏。计时旁箭头可重新展开或收起过程；不删除原文、不影响其他轮次。刷新快照中已有 final 或 final 后续中断时，过程默认仍保持折叠。该展示切换不代表轮次已经终态，不提前开放复制，计时、取消与复制继续遵守各自的完成条件。

展开入口仅保留计时旁的箭头图标，文字说明通过悬停提示和无障碍标签提供。计时与分隔线始终在过程区之外；过程作为整块区域在分隔线下方展开或收起，利用正常文档流连续推移下方结果，不逐条卸载消息。关闭列表滚动锚定，避免浏览器在高度过渡时自动补偿滚动、带动分隔线；折叠内容禁止键盘聚焦并对辅助技术隐藏。

手动展开或收起过程时，暂时隔离该次布局动画产生的尺寸变化，不触发尾部跟随，动画结束后也不补滚到末尾。原跟随状态保留，后续真正的流式内容更新继续按原模式处理；用户在动画期间主动上滑仍会取消跟随。

手动停止成功后，用户消息与已生成内容保留，intermediate 过程默认收起，计时旁的箭头仍可展开查看和复制最后一个消息块。停止不把消息数组清空；停止前正在追随时定位回最后一个用户问题，避免收尾布局变化将内容带出视口。停止失败不伪装终态，恢复原来的跟随状态。

复制按钮只出现在本轮最后一个消息块：正常情况下必须为已完成的 final，并等待短缓冲文本实际渲染完毕；手动取消成功后，也允许复制本轮最后一个已显示的非空消息块，包括中断的文本。前面的过程消息不提供复制，仍在输出或展示尚未追赶完成时不显示按钮；点击处理函数再次校验条件。只复制该块的原始 Markdown，不拼接历史过程、计时或操作说明。

## 对话区域宽度

桌面端左右区域通过玻璃切面分隔，切面中部提供悬停高亮的拖动握柄。向右拖动可扩大对话区域，向左拖动可缩小；对话区域最小保留 `360px`，右侧最小宽度及窄屏布局遵循[合同库档案筛选](contract-library.md#布局与使用)。握柄支持左右方向键微调，`Home` 和 `End` 分别调整到最小和最大宽度。窄屏上下布局不提供宽度调整。

## 验证重点

- 首次发送时，手绘提示不会突然消失，用户消息不会突然出现。
- 真实 SSE 不受入场动画阻塞，未收到业务输出时不产生示例答复。
- 输入框从默认高度扩展至最大高度时，手绘提示位置保持不变。
- 长问题、短问题和仅附件消息都能得到稳定的会话名称。
- 会话标题与历史菜单中的名称保持一致。
- 历史会话重命名后，菜单和当前会话标题同步更新。
- 首次发送后仍保留一个可用的空白“新对话”。
- 一个会话等待回复时，其他空白会话仍可输入和发送。
- 等待回复时可通过停止按钮取消当前轮次，发送新草稿可替代当前轮次。
- Markdown 常用语法能够正确渲染，原始 HTML 不会作为页面节点执行。
- 回放去重、分包解析、快照恢复、刷新定位和取消竞争不会造成重复文字或跨会话串流。
- 创建失败保留草稿；输入超限、认证失效、记录清理及断线均可观察。
- 拖动分隔握柄时左右区域连续调整，且不会突破双方最小宽度。
