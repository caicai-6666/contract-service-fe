# 智能助手会话交互

> 本文说明合同库智能助手原型中已经确认的会话交互边界，不定义后端会话存储或模型接口。

## 空会话与首次发送

空会话展示手绘提示，提示层独立于输入框高度，不随输入框伸缩移动。

用户首次发送消息时：

1. 手绘提示先快速向上淡出，并完全退出消息区。
2. 短暂间隔后，首条用户消息从输入框方向上浮至消息区顶部，退出与进入过程不重叠。
3. 首条用户消息完全就位后，才展示助手的回复状态并生成助手消息。
4. 后续消息使用较短的上浮进入动画，同样保持用户消息先于助手回复就位。

等待助手回复期间，发送按钮切换为白色方形停止图标并保持可操作。点击后只终止当前会话尚未完成的回复，输入框随即恢复；其他会话的回复状态不受影响。

系统启用减少动态效果时，不执行上述位移和渐变动画，但保持相同的最终布局与状态变化。

## 会话名称

首次发送后，当前“新对话”使用首条问题生成名称，并同步显示在当前会话标题和历史会话菜单中。

命名完成后，历史菜单顶部立即补充一个新的空白“新对话”；当前会话保持激活，用户可随时切换到该空白会话继续提问。每个会话独立维护回复状态，切换到新会话时不会被其他会话中尚未结束的回复锁定。

- 连续空白归一化为一个空格。
- Markdown 消息取首个有效文本行作为名称，并去除常见的标题、列表和行内格式标记。
- 名称保留前 `12` 个字符。
- 超出长度时追加 `…`。
- 仅发送附件时优先使用首个附件名称；无法取得名称时使用“附件分析”。

历史菜单中的每个会话均可原地重命名。`Enter` 或点击输入框外保存，`Esc` 取消；空名称不会覆盖原名称。手动命名的空白会话首次发送消息时保留自定义名称，不再被自动命名规则覆盖。

该规则仅用于当前前端原型命名，不代表后端会话标题契约。

## 消息呈现

消息区采用简约正文流：用户消息使用右侧轻量底色区分，助手消息不展示头像、徽标、气泡边框或阴影，直接以正文形式展示。

用户与助手消息均支持 Markdown，覆盖段落、标题、列表、引用、链接、行内代码、代码块和表格等常用语法。为避免将消息内容直接注入页面，原始 HTML 不参与解析；消息中的链接在新窗口打开，并使用安全的窗口隔离属性。

助手消息顶部展示处理耗时与默认折叠的处理路径。处理路径只表达面向用户的阶段摘要，不展示模型内部推理。消息底部提供复制、创建会话分支和消息时间；桌面端仅在悬停消息或键盘聚焦操作区时显示，触屏设备保持可见。

“复制”保留回复的原始 Markdown 文本。“分支”复制当前会话截至该回复的消息并创建独立会话，后续输入不会影响原会话。

## 对话区域宽度

桌面端左右区域通过玻璃切面分隔，切面中部提供悬停高亮的拖动握柄。向右拖动可扩大对话区域，向左拖动可缩小；对话区域最小保留 `360px`，右侧区域最小保留 `480px`。握柄支持左右方向键微调，`Home` 和 `End` 分别调整到最小和最大宽度。窄屏上下布局不提供宽度调整。

## 验证重点

- 首次发送时，手绘提示不会突然消失，用户消息不会突然出现。
- 用户消息完成上浮前，不显示助手的回复状态或回复内容。
- 输入框从默认高度扩展至最大高度时，手绘提示位置保持不变。
- 长问题、短问题和仅附件消息都能得到稳定的会话名称。
- 会话标题与历史菜单中的名称保持一致。
- 历史会话重命名后，菜单和当前会话标题同步更新。
- 首次发送后仍保留一个可用的空白“新对话”。
- 一个会话等待回复时，其他空白会话仍可输入和发送。
- 等待回复时可通过停止按钮终止当前会话，终止后不会再补发原型回复。
- Markdown 常用语法能够正确渲染，原始 HTML 不会作为页面节点执行。
- 处理路径可展开和收起；复制保留原始 Markdown；创建分支后原会话保持不变。
- 拖动分隔握柄时左右区域连续调整，且不会突破双方最小宽度。
