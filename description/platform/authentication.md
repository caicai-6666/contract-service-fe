# 前端登录与鉴权

> 本文说明审核用户登录、浏览器会话保存和受保护请求的前端边界。后端密钥配置、免登码生成与服务端过期策略以后端接口契约为准。

## 登录流程

登录页只收集审核用户密钥，通过合同 API 基础路径下的 `POST /auth/login` 发送 JSON 请求。请求体仅包含非空的 `secret_key`，前端不提交用户名称，也不在浏览器中保存原始密钥。

登录成功后，前端仅读取响应中的 `login_code` 和 `user_name`，建模为 `loginCode`、`userName`，两者均须为非空字符串。所有已登录用户均可使用全部业务功能，不读取或存储用户等级。工作台使用用户名称展示审核身份，免登码作为后续受保护请求的 Bearer 凭据。

登录失败时保持在登录页：`401` 展示后端提供的统一无效密钥提示，`422` 展示请求格式提示，网络失败和其他服务异常展示可重试信息。登录请求进行期间禁止重复提交。

## 会话边界

免登码与审核人名称保存在 `sessionStorage`，同一标签页刷新后可恢复登录，关闭标签页后不继续保留。旧缓存只要认证字段有效即可恢复，多余字段在读取时被丢弃并回写清理后的缓存；缺失或无效的认证字段仍会清除会话。浏览器禁用会话存储时，前端退回当前页面内存。

退出登录会立即清除本地免登码和审核人名称。前端不调用服务端撤销接口，因为当前接口契约未提供该能力。

## 受保护请求

登录后统一开放合同库、处理流、合同入库、合同删除及注意事项管理。前端不按用户等级隐藏入口、拦截路由或拒绝请求。后端也须同步移除等级授权规则，前端不会将服务端拒绝伪装为成功。

登录认证、会话和任务归属校验、运行状态限制、删除确认继续保留；`can_interrupt` 表示任务当前能否中断，与用户等级无关。服务端返回 `403` 时展示请求被拒绝，不将其当作登录过期；`401` 统一清理登录。

受保护的合同 API 应通过 `contractApiFetch` 调用。该入口统一附加：

```text
Authorization: Bearer <login_code>
```

若受保护接口返回 `401`，统一请求入口会清除本地会话并通知根页面返回登录界面。健康检查和登录接口不通过该入口调用。

生产构建使用 `/contract/api` 作为合同 API 基础路径。Vite 开发模式自动在该路径前增加 `/dev`，浏览器因此请求 `/dev/contract/api`；该请求先由 Nginx 去除 `/dev` 并映射到开发服务器，后续仍按 `/contract/api` 处理。开发模式需要通过该 Nginx 入口访问页面，直接访问 Vite 端口时不具备去除 `/dev` 的映射能力。

## 验证范围

- 验证登录请求的方法、地址、请求头和请求体均符合接口契约。
- 验证成功响应进入工作台、显示审核人名称并保存免登码。
- 验证页面刷新恢复当前标签页会话，退出登录清除会话。
- 验证 `401`、`422`、其他服务错误和网络失败不会进入工作台，并展示可理解的错误。
- 验证统一受保护请求携带 Bearer 免登码，响应 `401` 时回到登录页。
