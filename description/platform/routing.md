# 前端页面路由

> 本文说明工作台页面路由、基础路径和部署回退要求。登录鉴权行为见[前端登录与鉴权](authentication.md)。

## 路由表

工作台使用 Vue Router 的 HTML5 History 模式。当前路由如下：

| 路径 | 页面 |
| --- | --- |
| `/` | 重定向到 `/library` |
| `/library` | 合同库 |
| `/ingestion` | 合同处理流 |
| `/network` | 关系网 |
| 其他路径 | 重定向到 `/library` |

路由历史以 Vite 的 `import.meta.env.BASE_URL` 为基础。当前 `base` 为 `/dev/knowledge-accumulation/contract/`，因此开发环境中的完整页面路径分别是 `/dev/knowledge-accumulation/contract/library`、`/dev/knowledge-accumulation/contract/ingestion` 和 `/dev/knowledge-accumulation/contract/network`。

合同库、处理流和关系网在登录后完成渲染，并在工作台三页面轨道中持续挂载。用户在模块之间切换时，各自的会话、已选择文件、处理任务、流程状态和本地校对内容继续保留。不可见页面暂停不必要的计时和交互监听；重新进入时恢复布局测量，仍需保持同步的处理事件连接不被中断。合同库保留原有双栏空间，右侧展示[正式合同目录与档案筛选](../features/contract-library.md)，实例、筛选及滚动位置持续保留，返回时不重复请求。首次档案展示等待工作台入场与初始数据布局完成；目录通过手动刷新更新，相同结果不重复播放列表动画。

顶部导航依次为合同库、处理流、关系网。用户名右侧的信箱按钮为工作台共享入口，打开[审核日志](../features/contract-ingestion.md#审核日志)；弹窗由根页面管理，三个模块均可访问，切换模块关闭弹窗；登录失效或切换账号时销毁工作台并释放缓存。工作台导航按模块顺序移动三页面轨道：从合同库进入处理流时，已经渲染在右侧的处理流随轨道进入视口；返回合同库时反向移动。切换过程始终同时呈现当前页和相邻目标页，而不是在路由变化后临时挂载目标组件；顶部导航指示器同步滑动。系统启用减少动态效果时直接切换最终页面。

## 容器与缓存生命周期

工作台三个页面沿用持续挂载与 `active` 控制，提供与 KeepAlive 相同的状态保留，同时维持三页面轨道切换。不要改成随路由销毁，也不要在外层重复包装没有失活条件的 KeepAlive。

合同预览的轻量外壳首次打开后保留；注意事项、合同关联和摘要气泡使用 KeepAlive，按合同 ID（面板另含类型）区分实例，各缓存边界最多保留最近使用的 20 个实例。关闭浮层、切换合同再返回会保留已加载数据、编辑内容及列表位置，不重复请求。失活时关闭确认框、搜索气泡和文字气泡，停止二次确认计时并暂停相关全局监听；重新激活不重复提交写请求。关联发生写操作后，其他合同的旧关联实例下次激活重新读取；写结果未确认时，重新打开面板核对列表。合同库手动刷新同时清除预览元数据缓存。

审核日志容器持续挂载，关闭后保留栏目、筛选、选择、滚动和完整加载的数据，重新打开直接复用；被关闭或切换中断的列表下次进入重新读取。手动刷新获取最新审核结果，提交入库或删除申请后对应列表失效，避免新申请被旧缓存遮住。PDF 继续复用已有容量受限的 Blob 缓存；关闭预览释放阅读器、Worker 和临时 URL，不无限保留 PDF 页面画布。缓存仅存在于本次工作台内存，刷新浏览器、身份失效或账号变化时释放；SSE、运行快照和用户主动刷新仍按原有同步规则执行。

关系网使用正式合同目录及一跳关系接口展示可交互的无向关系图；功能与数据边界见[合同关系网](../features/contract-network.md)。

## 登录边界

路由表示用户希望访问的工作台模块，登录状态仍由根页面统一管理。进入页面先读取统一入口共享的 `access_token` 并请求 `/auth/me`，确认身份后才挂载工作台。缺少凭据、401 或 403 显示对应的提示卡片和返回统一入口链接；网络或服务异常可重试。目标路由始终保留，验证成功后直接进入对应模块。共享 token 更新时销毁旧工作台及其缓存，重新验证身份；不复用旧用户页面。

## 部署要求

History 模式下，浏览器直接访问或刷新 `/dev/knowledge-accumulation/contract/library`、`/dev/knowledge-accumulation/contract/ingestion`、`/dev/knowledge-accumulation/contract/network` 等前端路径时，Nginx 必须将请求回退到前端 `index.html`。静态资源和 `/dev/knowledge-accumulation/contract/api` 请求不得进入该回退规则；API 仍按[前端登录与鉴权](authentication.md)中说明的链路转发。

生产页面和静态资源的基础路径为 `/knowledge-accumulation/contract/`。外层网关必须为合同子路径配置比统一入口 `/knowledge-accumulation/` 更具体的转发规则，开发环境同理；否则合同页面可能收到统一入口的 HTML。这种情况属于网关路由错误，不应作为合同平台的登录失败处理。

开发服务器使用 `node_modules/vite-cache` 保存依赖预打包结果，避免网关拦截隐藏目录；3d-force-graph 与 Three.js 在此预打包，减少首次加载的模块请求。开发服务器不会将 `pdfjs-dist` 放入 Vite 的 `node_modules/.vite/deps` 预打包目录。PDF.js 保持按需加载，但使用不含 `/.vite/` 隐藏目录段的标准模块地址，以兼容会拦截隐藏目录 URL 的 Nginx 规则。修改此项配置后必须重启 Vite 开发服务器。
