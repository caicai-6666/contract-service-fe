# 前端页面路由

> 本文说明工作台页面路由、基础路径和部署回退要求。登录鉴权行为见[前端登录与鉴权](authentication.md)。

## 路由表

工作台使用 Vue Router 的 HTML5 History 模式。当前路由如下：

| 路径 | 页面 |
| --- | --- |
| `/` | 重定向到 `/library` |
| `/library` | 合同库 |
| `/ingestion` | 合同处理流 |
| `/network` | 关系网 |
| 其他路径 | 重定向到 `/library` |

路由历史以 Vite 的 `import.meta.env.BASE_URL` 为基础。当前 `base` 为 `/dev/knowledge-accumulation/contract/`，因此开发环境中的完整页面路径分别是 `/dev/knowledge-accumulation/contract/library`、`/dev/knowledge-accumulation/contract/ingestion` 和 `/dev/knowledge-accumulation/contract/network`。

登录后仅加载当前路由对应的业务页。合同库、处理流和关系网在首次访问时下载代码并挂载，访问后在工作台三页面轨道中持续挂载。用户在模块之间切换时，各自的会话、已选择文件、处理任务、流程状态和本地校对内容继续保留。不可见页面暂停不必要的计时和交互监听；重新进入时恢复布局测量，仍需保持同步的处理事件连接不被中断。合同库保留原有双栏空间，右侧展示[正式合同目录与档案筛选](../features/contract-library.md)，实例、筛选及滚动位置持续保留，返回时不重复请求。首次档案展示等待工作台入场与初始数据布局完成；目录通过手动刷新更新，等待请求和退场完成后统一切换一次，即使结果相同也播放该次刷新动画。

顶部导航依次为合同库、处理流、关系网。用户名右侧的信箱按钮为工作台共享入口，打开[审核日志](../features/contract-ingestion.md#审核日志)；弹窗由根页面管理，三个模块均可访问，切换模块关闭弹窗；登录失效或切换账号时销毁工作台并释放缓存。工作台导航按模块顺序移动三页面轨道：从合同库进入处理流时，右侧页面随轨道进入视口；返回合同库时反向移动。三页面轨道的容器始终保留，首次访问尚未下载完成的业务页在目标容器中显示居中加载动画；代码就绪后展示业务内容，已访问的页面切换时直接复用实例。顶部导航指示器同步滑动。系统启用减少动态效果时直接切换最终页面。

## 容器与缓存生命周期

`AsyncWorkspacePage.vue` 在对应页面第一次激活时执行动态导入，加载中可继续切换其他页面；模块失败或等待超时（开发 60 秒、构建 20 秒）显示错误和重试，迟到成功可恢复。根工作台销毁后，旧加载结果不再恢复组件。路由仅负责地址匹配和 `sectionIndex`，使用轻量路由标记，不再重复导入业务页面。

工作台三个页面首次访问后沿用持续挂载与 `active` 控制，提供与 KeepAlive 相同的状态保留，同时维持三页面轨道切换。不要改成随路由销毁，也不要在外层重复包装没有失活条件的 KeepAlive。

合同预览的轻量外壳首次打开后保留；注意事项、合同关联和摘要气泡使用 KeepAlive，按合同 ID（面板另含类型）区分实例，各缓存边界最多保留最近使用的 20 个实例。关闭浮层、切换合同再返回会保留已加载数据、编辑内容及列表位置，不重复请求。失活时关闭确认框、搜索气泡和文字气泡，停止二次确认计时并暂停相关全局监听；重新激活不重复提交写请求。关联发生写操作后，其他合同的旧关联实例下次激活重新读取；写结果未确认时，重新打开面板核对列表。合同库手动刷新同时清除预览元数据缓存，列表切换规则见[合同库档案筛选](../features/contract-library.md#正式合同目录接口与模型)。

审核日志容器持续挂载，关闭后保留栏目、筛选、选择、滚动和完整加载的数据，重新打开直接复用；被关闭或切换中断的列表下次进入重新读取。手动刷新获取最新审核结果，提交入库或删除申请后对应列表失效，避免新申请被旧缓存遮住。PDF 继续复用已有容量受限的 Blob 缓存；关闭预览释放阅读器、Worker 和临时 URL，不无限保留 PDF 页面画布。缓存仅存在于本次工作台内存，刷新浏览器、身份失效或账号变化时释放；SSE、运行快照和用户主动刷新仍按原有同步规则执行。

关系网使用正式合同目录及一跳关系接口展示可交互的无向关系图；功能与数据边界见[合同关系网](../features/contract-network.md)。

## 登录边界

路由表示用户希望访问的工作台模块，登录状态仍由根页面统一管理。进入页面先读取统一入口共享的 `access_token` 并请求 `/auth/me`，确认身份后才挂载工作台。缺少凭据、401 或 403 显示对应的提示卡片和返回统一入口链接；网络或服务异常可重试。目标路由始终保留，验证成功后直接进入对应模块。共享 token 更新时销毁旧工作台及其缓存，重新验证身份；不复用旧用户页面。

## 部署要求

History 模式下，浏览器直接访问或刷新 `library`、`ingestion`、`network` 页面都应返回前端 `index.html`。开发环境由外层网关保留 `/dev/knowledge-accumulation/contract/` 转发给 Vite，由 Vite 提供页面回退及开发 API 代理；生产容器 Nginx 只服务 `/knowledge-accumulation/contract/`，不提供 `/dev` 路径。API 与缺失的构建资源、PDF.js 文件不得回退为 HTML；API 转发规则见[前端登录与鉴权](authentication.md)。

生产页面和静态资源的基础路径为 `/knowledge-accumulation/contract/`。外层网关必须为合同子路径配置比统一入口 `/knowledge-accumulation/` 更具体的转发规则，开发环境同理；否则合同页面可能收到统一入口的 HTML。这种情况属于网关路由错误，不应作为合同平台的登录失败处理。

开发服务器使用项目根目录的 `cache/vite` 保存依赖预打包结果，避免网关拦截隐藏目录，也避免安装依赖时清理 `node_modules` 下的额外目录；3d-force-graph 与 Three.js 在此预打包，减少首次加载的模块请求。开发服务器不会将 `pdfjs-dist` 放入 Vite 的 `node_modules/.vite/deps` 预打包目录。PDF.js 保持按需加载，但使用不含 `/.vite/` 隐藏目录段的标准模块地址，以兼容会拦截隐藏目录 URL 的 Nginx 规则。修改此项配置后必须重启 Vite 开发服务器。


## 开发资源压缩与预热

开发服务器通过 `config/developmentCompression.js` 和仅在 Node 侧运行的开发依赖 `compression`，在进入 FRP 隧道前压缩文本资源。客户端按 `Accept-Encoding` 协商 Brotli 或 gzip；gzip 等级为 6，Brotli 沿用中间件默认等级 4，阈值为 1 KiB。仅处理开发前缀下成功的 GET 文本资源（HTML、JavaScript、CSS、JSON/source map、SVG）；API、凭据路径、SSE、`no-store`、`no-transform`、Range、HEAD 和二进制资源不压缩。HMR WebSocket、Bearer 与请求代理行为不变，保留 Vite ETag、304 和 HTTP 缓存，中间件维护 `Vary: Accept-Encoding`。外层代理应保留编码及 Vary 响应头。

`server.warmup.clientFiles` 仅预热业务入口和默认合同库的转换结果，减少重启后首访转换等待，不预请求业务数据。处理流、关系网页面以及现有图引擎与 PDF 运行时继续按需加载，不加入首屏预热列表。缓存目录不进入 Git 或 Docker 上下文；新增配置模块由 Dockerfile 显式复制。生产静态服务器的压缩策略不由此开发插件改变。

修改依赖或配置后安装依赖并重启 Vite。验证需比较相同缓存条件下的脚本/样式请求数与实际传输字节，检查直接访问及刷新深层路由、首次加载失败重试、页面实例及草稿保留、HMR、PDF Worker 和 SSE 首事件时序。首次切换可能需要等待目标代码；本机传输量下降不等同于公网或钉钉打开耗时同比下降，FRP、网关和客户端需单独实测。
