## 文档职责

| 分类 | 回答的问题 | 典型内容 |
| --- | --- | --- |
| 项目原则 | 开发时长期遵循什么边界和质量标准？ | 范围、设计原则、质量原则、变更流程 |
| 专题设计 | 为什么这样设计，模块如何协作？ | 架构、流程、状态、关键取舍 |
| 功能说明 | 一个功能负责什么，如何使用？ | 用途、接口、依赖、限制、验证方式 |
| 参考契约 | 精确且可执行的规则是什么？ | 字段、类型、Schema、配置和协议 |
| 运行维护 | 如何配置、启动、部署和排障？ | 环境、命令、监控、常见故障 |

项目原则只保留稳定的全局思想；具体行为进入相应专题；精确约束优先由机器可读定义和程序校验执行。

## 扩展约定

1. 一个规则、契约或流程只保留一份完整的权威说明，其他文档通过相对链接引用。
2. 新文档只记录已经确认、具有持续维护价值的信息，不复制临时讨论和猜测。
3. 新建、移动或重命名文档时，应同步维护本导航及所有相关链接。
4. 文档结构、命名和排版统一遵循[文档撰写风格手册](documentation.md)。
